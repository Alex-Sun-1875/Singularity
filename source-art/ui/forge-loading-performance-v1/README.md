# 工坊加载真实耗时基线

只读测量 v2 冻结快照 `88df3f1acbf8…`，未修改生产源码、构建、暂停游戏或发放装备。缓存保持默认开启，没有人为延迟或网络限速。使用正常 test 初始人物与真实菜单；初始库存、穿戴、等级不变，所有服务与浏览器已关闭。

`baseline-hardware.json` 是本机实际 RTX 3080 / ANGLE D3D11 的有效记录。第一次默认 headless 被浏览器选择为 SwiftShader，原始 `baseline-headless-default.json` 单独保留，不能用它的 679ms 解释用户硬件。

首开请求了 **20 张工坊 PNG + 20 份导入元数据**；PNG 合计 749,110 字节，新增解码纹理约 2.48MB。此前故障注入记录的 14 张是被拦住的在途子集，不是总数。并行出现的两张场景地面图不计入工坊资源。

工坊图片约在点击后 63ms 收完，完整页面约在 186ms 出现，中间有一个 77ms 主线程长任务。该间隔包含解码/上传、建页与正常场景帧工作；浏览器 ResourceTiming 不能将它全部精确归为“图片解码”。页面准备结束到本帧画完仅 2.5ms。热重开及页签没有再次下载工坊图片。

常驻总量 16.61MB 包含已经驻留的公共 UI，不是这次下载量。`preloadOwned` 的额外 await 在这个初始人物上没有发起装备图片请求；现成 `GameResources` 已有 cache-get 微任务快路，两者不能被误报成新发现的下载浪费或待补功能。

完整请求、分段时间、资源枚举和有条件的优化建议见 `summary.json`。本机 loopback 文件服务与桌面 GPU 数据只能区分等待来源，不能代替 TapTap 真机、CDN 或移动网络延迟结论。未因此直接实施优化。

# 雷系其余技能优化 v12

本轮实际接入当前 Cocos 主工程，重点为雷霆战印、扇雷横扫、雷光护幕，并统一奔雷附雷和雷冠庇护的表现。沿用 v11 的白亮核心／蓝紫外缘、主干与连锁粗细、真实命中后的地面雷晕；没有增加雷系范围法阵。

## 表现与规则

- 雷霆战印仍是移动后雷系命中自动触发的强化，不添加手动按钮。三次附雷用真实握柄上的双股蓄电和三个短电纹表示，随当前剩余次数变化；第三次真实普攻附雷强化接触。奔雷与战印读取同一份三次附雷状态，不复制为六次。
- 扇雷横扫沿用原扇面和两次真实伤害，在实际受击区域中加入短促、破碎的横向电流前沿，两拍方向相反。前沿只在真实打击后出现，是胸口高度的能量扫击，不是地面扇面轮廓或预警；继续遵守已有 LOS，不增加目标或伤害。
- 雷光护幕使用贴身的开放电弧肋条体现前后纵深。一次真实直接命中触发压缩爆亮，减伤消耗后保留较弱的移动加速表现，三秒结束后消散。
- 雷冠庇护读取真实护盾状态，以较克制的肩部电弧呈现；和护幕同时存在时只补肩部短电纹，避免叠出两层厚护罩。
- 附雷命中的地面残留按受击目标刷新，避免三个普攻 action ID 在同一位置叠出三团浓雾。其余 v11 地面雷晕时长与资源保持。

复用已认可的电光图集、Cocos 原生动态网格与现有地面雾池，没有新图片、生成模型、第三方依赖或额外灯光。新增 `ThunderSupportEffects.ts` 只组织呈现，不查找新目标、制造命中或提交伤害。`accent` 纹理角色与目标连接角色分开，弯曲的护幕／扫击不会被连线的直线走廊错误压平。

## 实际录制

```powershell
npm run build
# 首次录制前固定完整产物；web 目录已存在时先保留旧副本，不合并不同构建。
if (Test-Path src/.tmp/thunder-family-v12/web) { throw '录制副本已存在，请先保留旧副本再建立新副本。' }
Copy-Item -LiteralPath src/cocos/build/concept-2d -Destination src/.tmp/thunder-family-v12/web -Recurse
node source-art/skills/thunder-family-v12/capture.cjs
& F:/Models/ComfyUI_windows_portable/python_embeded/python.exe source-art/skills/thunder-family-v12/review.py
```

当前完整副本已经建立，可直接执行后两条命令复录。本次使用 NVIDIA RTX 3080 / ANGLE D3D11 的本地无头 Chromium，预热阶段用独立时钟推进原生 Director，进入逐帧录制前清除预热时钟；不替换原生渲染器或技能模块。录制副本与常规预览目录隔离，其他构建不会改动正在录制的素材。

录制直接提供当前编译产物，没有替换玩法或特效模块。`fixture-patches.cjs` 仅改造已有靶场的相机／目标设置与真实输入：

1. 连续移动后用雷矛真实命中触发战印，再用真实普攻消耗三次附雷。
2. 在正常技能扇面内放置八个训练目标，两次打击真实触发雷冠庇护。
3. 护幕生效后让训练敌人执行实际攻击，记录一次真实减伤反馈及后续移动。

不直接设置附雷次数、护幕减伤或护盾值，也不手工发出伤害与命中事件。训练敌人的攻击开关仅控制演示时机，实际攻击、判定和伤害仍由游戏处理。

原生帧及逐帧事件位于 `src/.tmp/thunder-family-v12/final/implemented/`，输出在 `media/`。审计会核对自动触发、3→2→1→0 次数、真实第三击、握柄锚点、横扫两拍方向、真实护盾及护幕受击／到期状态，再输出各招与合并动画。

本次实际录制和审计通过：战印在真实移动约 1.33 米并命中后自动触发，三次附雷依次消耗，电纹随实际握柄运动；横扫摆放八个训练目标，两拍各有五次真实命中，未把遮挡／范围外目标补成命中，两道电流前沿方向相反，雷冠庇护真实触发一次；护幕承受一次真实直接攻击，消耗一次减伤，随后移动约 1.84 米，三秒结束后电弧清除。已查看峰值、衔接序列、握柄与护幕细节，最终美术偏好待用户评审。

类型检查、核心类型检查、155 项现有测试和本地 test Web 构建通过。美术验收待用户反馈；本地 Cocos Web 不替代 TapTap 真机效果与性能验收。没有打包、上传或发布，版本未递增。

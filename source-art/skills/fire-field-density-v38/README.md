# 焚焰火域密度调整 v38

按用户圈出的焚焰火域增加细焰覆盖，让原先稀疏的火纹连成更饱满的连续火面。复用已经确认的 v30 原稿像素与原生连续曲面，无新增生成图片或依赖。

`densify.py` 在原 16 帧图集中烘焙两层同向运动的错位细焰，透明度分别为 0.72、0.42，原有亮纹保留在前层。保持原 U 周期接缝和纵向软边；两道低卷焰的权重由 0.18 调至 0.30。原资源路径和 UUID 保持，生产纹理仍为 1024×512，RGBA8 纹理占用仍为 2 MiB。单个火域仍为一个渲染器、575 顶点、960 三角形，片元仍只采样两次，没有增加独立火苗卡片。

原稿来源、处理参数和候选纹理哈希见 [素材记录](assets/provenance.json)。素材处理结果与实景验收分开记录；用户最终美术反馈及 TapTap 真机显示、GPU 与温升均待验证。

本地使用正常 test 规则导出，不升版、不制作 TapTap 包。复用已有训练场与 v30 固定步长录制方法，在全新浏览器上下文里从正常 1 级旅程进入独立靶场；靶场角色为既有临时 80 级、技能 1 级，不写回正常成长存档。录制不替换场景特效或修改镜头。

对照覆盖空地轮廓、五靶真实命中和减少动态三种状态，每段 7 秒；比较实际技能事件、命中、伤害、冷却、网格、绘制计数及结束清理。具体结果以 [验证记录](verification.json) 为准。[前后画面](native-before-after.png) 仅裁切、并排和加说明，原始画布帧位于记录中的缓存目录。

`before/` 为首次稳定录制。`after/` 的中间录制虽然已取得三段画面，但结束校验时共享构建目录被另一项构建替换，不能作为最终构建稳定性证据；最终使用逐文件校验的固定副本补录至 `after-stable/`，副本清单见 [snapshot.json](snapshot.json)。最终图、技能事件及导出纹理匹配以这次补录为准。

空地和减少动态的全场绘制计数逐帧一致；包含命中表现的群靶场景有 70／210 帧计数不同，实测峰值均为 98 次绘制、112870 三角形。三个场景的火域网格和技能事件均完全一致，群靶均为 25 次命中、865 伤害，结束无残留。这里只核对本地渲染数量，不作为真机帧时间或耗电结论。

验证脚本：`capture.cjs <阶段> [固定构建相对路径]`、`compare.py`。本轮类型检查和 181 项既有测试通过，无新增测试用例。

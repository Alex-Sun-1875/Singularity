# 统一护盾：实际接入

用户于 2026-11-16 以“可以照这个实现一下吧”批准本目录四系护盾稿及其共同动画。原来的设计动画保留为参考；实际运行证据与生成稿、美术决定分别记录。

## 现行实现

`UnifiedShieldEffects.ts` 复用 Cocos 原生 `primitives.sphere`、`MeshRenderer`、`Material` 和资源适配层，创建一个真正的 3D 椭球壳。不是将设计图的角色和背景作为贴图导入游戏。24 段球体共 625 顶点、1152 三角形，以前后两个透明面通道绘制。材质开启深度测试、关闭深度写入，角色与场景仍用实际深度遮挡。

四系共用几何、材质、轮廓光、透明薄膜、0.32 秒形成、轻微呼吸、0.22 秒局部接触波纹、0.48 秒自然退亮、0.28 秒提前击破溶解。仅 `shieldTint` 与 `motifChannel` 不同。现有四系纹样剔除地圈、中心徽记和直辐条后，粗化并打包到一张 512×512 RGBA 数据图的四个通道，以相同 UV 映射到曲面。没有添加地面范围圈、粒子发射器、灯光、物理碰撞或依赖。

实际护盾量与到期时间来自 `player.shield`、`combat.buffs.shieldUntil`，所以主动技能、被动和装备授予的真实护盾共用同一呈现。颜色和纹样由当前职业读取，不依赖旧主动技能 ID 的遗留标记。护盾刷新会延长现有显示，不叠第二个壳或反复播放成形。

真实 `hurt` 事件的 `absorbed` 驱动接触波纹；能找到来源敌人时使用该侧法线，无方向来源时在角色前方反馈。持续显示随人物位置、地面高度与朝向更新；暂停保留原时间，换场、死亡、销毁时清除。资源走 `GameResources` 与既有 `vfx/` 分包路由，加载阶段预热材质，运行时重复使用同一个网格和材质。

已移除战士／火系旧甲片与羽状护盾，以及雷冠被动的旧肩部护盾叠层。雷光护幕的真实减伤电弧保留，它是不同的减伤状态，不借此次改动变成吸收护盾。普通受伤与伤害吸收的公共反馈仍走既有流程。

## 不改变的玩法

没有改动护盾数值、持续时间、触发来源、技能槽位、冷却、吸收／减伤规则或任何伤害。不为弓系新增主动护盾；弓系配色用于其装备等来源实际产生的护盾。

## 验证口径

运行录制 `capture-runtime.cjs` 只提供本轮正常编译的 `build/concept-2d`，不覆盖脚本、纹理或着色器响应。战士和火系片段施放实际主动技能。弓系、雷系外观对照调用既有权威护盾规则生成测试状态，明确标记 `state-fixture`，不把它们当成已验证的被动／装备触发流程。受击调用既有伤害规则产生真实吸收事件；没有伪造命中消息。暂停和移动另有状态检查。

类型检查、已有护盾规则用例、Cocos Web 构建和运行画面分别记录。资源按既有 TapTap 适配路径接入；TapTap App 与目标手机真机的画面、深度和性能仍需真机验证，本轮没有制作发布包或提升版本。

# Qwen 本地角色一致性小样 v2

2026-11-07，按用户要求处理三个问题：背剑过短、站姿与跑动衣裤色不一致、正/背面跑步腿躯干比例显矮。全部生成式处理使用已经部署的本地 Qwen-Image-2.1-Turbo INT8，未下载新模型、未调用云端生图。代表帧完成后，按用户“应用到游戏”及“不用保留原件”的要求，已直接覆盖探索动作的4张运行图集与3个动作记录；未新增原件备份。

## 本轮方法

1. 原始素材来自现用站姿/跑步图集，来源和原件哈希见 `source-baseline.json`。统一512×768画布和400px/world，不对每个包围框单独拉满。
2. 已有像素先提供比例与剑长引导。站姿头部按1:1平移复用；手、靴、剑柄、固定点和原帽分层保护，避免全横带缩放导致手剑变形。
3. **实际运行本地 Qwen**：原生 VAEEncode + SetLatentNoiseMask，参考图通过 TextEncodeQwenImage21，Euler、CFG1、官方固定8步Turbo sigma。Qwen仅补绘腰髋膝、衣料遮挡揭露区和剑鞘中段衔接。
4. 模型原始RGBA保存在 `results/<case>/raw-model.png`，不做覆盖或美化。最终候选单独保存到 `final/`：按局部遮罩合成，过滤模型透明区域中的隐藏RGB，保留源alpha/轮廓，再分别校准背心、袖布、裤料的站姿参考Lab颜色。
5. 头部沿用站姿原像素时产生的领口接缝单独用原跑姿颈/领口像素修复；脸与发型核心、手、剑帽和靴不参与这项修复。该步骤与模型推理分开记录。

不是“只把整图交给模型重画”，也不是“只做像素处理而没有调用Qwen”。具体图形比例/原部件保护由本地工具负责，新接缝像素由实际Qwen补绘，颜色再由确定性局部校准约束。

- `final/run-back.png`：背跑剑同步约+26.4%，原帽整数平移(-28,+68)。真实鞘帽止点约(205,398)，没有把下方斜金衣摆当成剑尖。

- `final/run-right.png`：侧跑布料颜色校准，姿势、装备和透明通道保持原件。

`geometry-report.json`、`final-report.json`、`finalization-report.json` 与 `final/*-palette.json` 分别记录几何、原部件保护、模型RGB合成、色彩采样。Lab采样中位数接近只说明选定布料样本颜色接近，不能替代对整个人物和动作连续性的视觉判断。

## 运行与边界

`run-masked.py --case <name>` 复用 `http://127.0.0.1:8188` 的离线ComfyUI，只允许原生节点和本地文件，不静默覆盖已经提交的任务。`finalize.py` 负责局部合成及调色，`make-review.py` 生成对照图。

比例与剑帽工具复用了旧试验目录中的 Pillow/NumPy/SciPy 像素处理能力；不依赖已卸载的FLUX权重。新代码以接入、遮罩、合成和验证为主，没有安装新依赖或添加测试脚手架。

剑和衣料已是扁平图，隐藏衣料与部件matte仍是局部估计，不能保证等于未保存的原始分层工程。最初的四组代表帧随后扩展接入完整探索循环：4帧站姿、16帧行走、32帧跑步。其他相位使用本地确定性分层适配，不表述为逐帧重新调用Qwen。头部统一站姿1:1像素，正背跑按每相位原手/靴/装备遮挡调整；背剑13帧各用自身原帽仅整数平移；运动布料按同向站姿校色。持剑及其他动作保留原姿势。安装、裁切、原脚锚和实机核验记录见 [game-install](game-install/README.md)。

本地推理与Codex云端看图分开：为必要分区与缺陷检查使用少量缩略图/局部，不上传整套图集用于云端生成。最终核验见 `verification.json`，视觉记录见 `visual-review.json`。

# 移动攻击发热排查与屏幕外装饰优化

2026-11-12。用户确认 iPhone 14 上移动时使用剑、弓、火、雷都会明显发热，先以 S13 石场复现。跑动保持 5 米/秒、慢走 2 米/秒、原有 60 帧设置。本次没有 iPhone 的 CPU/GPU、温度或功耗采样，不能把下面模拟器数据换算成手机降温幅度。

## 找到的共同开销

详细采样把负担指向 Cocos legacy forward pipeline 的场景遍历、模型更新与渲染状态提交。石场约 989 个启用模型中，815 个是静态绘画装饰卡片。它们已有原生视锥剔除和实例化，815 个模型不等于 815 次绘制，但屏幕外模型仍在每台摄像机的场景列表中逐项检查。移动和攻击叠加人物、敌人、特效和 HUD 更新时，这部分固定开销仍然存在。

没有证据表明把跑速从较高值降为 5 米/秒足以解决所有武器的发热。本轮也没有测出稳定的 GPU 降幅，先消除有对照证据的 CPU 遍历浪费。

## 实现

`FlatWorldLayers.ts` 复用 Cocos 节点激活、AABB 与摄像机视锥接口，把静态视觉卡片按 8 米网格分组。组边界包含实际卡片大小，并额外留出 2 米边缘；视野外整组停用，活跃组继续交给引擎原有精确剔除和实例化。碰撞、原始地图节点、敌人和玩法状态不参与这项停用。

摄像机移动 0.25 米、旋转、缩放、窗口尺寸或投影裁剪参数变化时刷新粗剔除；使用当前帧公开摄像机更新接口。组重新进入视野时同步刷新遮挡淡化，避免人物静止而缩放窗口时沿用旧淡化状态。仅视觉节点重新分组，不卸载贴图或网格，因此不宣称降低常驻资源内存。

## 同一画面的归因对照

Android 14 x86_64 模拟器，4 核/4 GB，宿主 RTX 3080 硬件转译，Chrome 113；实际 Cocos 画布 1608×768。冻结同一个真实战斗帧的游戏逻辑，继续绘制；以关／开／开／关四个窗口采样，每个约 3.5 秒且超过 200 帧。没有逐方法计时包装。前后游戏时间均为 4.6494 秒。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 渲染主线程 CPU 均值 | 4.34 ms/帧 | 3.23 ms/帧 |
| 场景模型数 | 991 | 207 |
| 活跃静态卡片 | 815 | 31 |
| 绘制调用 | 202/帧 | 202/帧 |
| 三角形 | 196,750/帧 | 196,750/帧 |

此对照的渲染主线程耗时下降 **25.7%**，模型列表缩小约 79%。绘制调用和三角形量相同；同帧截图只出现 11 个像素的单通道 1 级差异。这支持“减少屏幕外模型遍历”的归因，不代表完整游戏 CPU、整个进程、GPU 或 iPhone 温度下降 25.7%。

## 实际移动攻击复核

同一编译版、同种子和装备，通过正常移动及普攻/技能输入，四系各两轮，每段 7 秒，第二轮颠倒开关顺序。弓使用按下并释放的输入，确实产生箭矢与命中。没有改敌人生命、伤害或战斗规则。总计 6,452 帧，无页面运行错误。

| 系别 | 优化前 CPU 样本 ms/帧 | 优化后 CPU 样本 ms/帧 | 两轮均值变化 |
| --- | --- | --- | --- |
| 剑 | 6.49、8.56 | 5.42、5.89 | 7.52 → 5.66 |
| 弓 | 7.97、6.56 | 6.79、6.79 | 7.27 → 6.79 |
| 火 | 6.39、7.45 | 5.60、5.47 | 6.92 → 5.54 |
| 雷 | 8.15、8.46 | 8.34、6.30 | 8.30 → 7.32 |

弓、雷样本有重叠及个别反向变化；真实战斗的命中、击杀与事件时序也略有不同。因此不把这些短样本均值当成四系稳定收益承诺。宿主 GPU 计数波动较大，没有可归因的稳定下降。CPU 指标是 CDP `Performance` 主线程 threadTicks 除以实测帧数；宿主 GPU 使用 qemu 进程 WDDM engine 累计计数差值，不能代表 A15 GPU。

初期逐方法 `performance.now()` 包装产生显著额外开销，仅用于定位；初期弓持续按住没有持续释放、粒子数读取字段也不正确。这些探索数据不用于上表或最终收益结论。最终移动对照已去除逐方法包装，正确读取 `getParticleCount()`。

## 画面与构建验证边界

S13 四种位置/缩放/旋转下，以引擎原生模型 AABB 和当前视锥为参照，所有原本可见卡片都保留活跃。城镇 S01、森林 S03、地下 U1-04 又各检查 844×390 和 932×430 两个横屏视口，包含窗口变化及拉远镜头；全部无遗漏、无运行错误。六组同帧截图最大通道差异 1–2/255，没有超过 8/255 的差异。这是功能渲染检查，不是手机帧率验收。

性能采样使用当时的 0.3.22 Web 编译快照；原始编译脚本与 SHA-256 已归档。最终源码另加入“组可见性变化时刷新遮挡淡化”的边界修复，该修复通过最终类型、Cocos 编译及包内编译标记核对。额外 Web 重建两次在 Creator 启动时遇到 Windows `UNKNOWN open engine.json`，未进入编译，因此画面证据仍来自前述核心分组编译版，不能宣称最后的边界修复也完成新 Web 画面验收。

打包期间其他工作继续修改职业资源和面板；首轮 0.3.23 保留审计但未交付，后续使用完整更新并通过类型与 120 项现有规则检查的源码生成 **0.3.24**。完整包 219.77 MB，本地主包审计 1.26 MiB。03:25:21 记录的 182 份非生成脚本在 Cocos 编译完成后的哈希复核一致；ZIP 于 03:26:50 完成，其他工作从 03:27:04 又修改人物、战斗与 HUD，这些后续修改已保留且不在本次不可变 ZIP 中。具体清单和包体哈希见发布验证文件。

待在 iPhone 14 的真实 TapTap 环境复测：相同亮度、充电状态、室温与画质下，石场分别静止、跑动、原地攻击、移动攻击，各持续 10–15 分钟，记录稳定阶段温度、帧率、内存和可获得的 CPU/GPU 指标。当前没有把本地通过表述成平台或真机验收，也没有上传包体。

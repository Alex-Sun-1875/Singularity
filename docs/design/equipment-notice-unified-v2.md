# 装备获得与地面掉落提示统一

2026-11-16。按用户要求，两类被动顶部提示统一采用[已确认的掉落 v2 稿](../../source-art/ui/loot-alert-v1/legendary-v2.png)。详细装备获得确认页继续遵循独立的[获得页 v3](equipment-acquisition-v3.md)。

## 实现

- `EquipmentPickupNotice` 使用同一个呈现流程，统一为优选 300×72 逻辑像素的切角铆钉金属框、深棕纹理内衬、左侧真实装备图与品质柔光、装备图旁左对齐的三行文字。品质与状态从距框左边 98 逻辑像素处开始，与 56 像素装备图框右沿保留 20 逻辑像素间距；用户随后要求装备名称再靠左一点，因此名称单独左移 4 至 94 逻辑像素，与图框间距为 16。原字号和行距保持不变，长名称省略时保留数量后缀。
- 右侧在 212—282 逻辑像素范围显示最多两项主要基础属性，复用 `equipmentBasePresentation` 的真实目录与当前等级成长数据，标签靠左、数值靠右。威力、生命、护甲与成长属性按已有顺序选取；没有基础数值加成时显示装备类型及等级要求。基础属性不混入强化、宝石、历史骰印或穿戴比较。实际宽度小于 290 逻辑像素时收起属性列，让主提示保留可读宽度。
- 获得提示显示「获得品质装备／装备名及数量／已收入行囊」；地面掉落显示「品质装备掉落／装备名／靠近自动拾取」，容量不足时第三行显示真实原因。品质颜色继续读取公共 `FeedbackPalette`，不将稀有装备改成橙色。
- 两类提示均复用原稿提取的 `loot-drop-panel-v1` 和公共 `UiSkin`／`DoubleGoldFrame`。包含完整内衬与透明轮廓的皮肤使用 `bakedSurface`，避免通用圆角底板在切角外露出黑色边角；默认公共面板的材质、阴影及圆角行为不变。
- 用户确认上述布局后，传奇与神器的装备图周围补充原有四角花纹。直接复用 `UiChrome.cornerOrnaments`，装饰容器为 72×68 逻辑像素，沿用公共角花的原始线宽，实际曲线内缩在通知边框内。纹饰位于柔光上方、真实装备图下方，保留装备主体、字号与右侧属性排版。普通至史诗沿用原来的简洁图标。
- 移除获得提示单独使用的胶囊框、底部饰线与扫光，保留既有淡入淡出及品质柔光。顶部位置按实际提示高度计算，与自动条保留 8 逻辑像素可见间距；存在首领提示或罗盘时沿原信息层级排布。
- 获得提示原有时长、队列优先级、地面提示的 24 秒累计可见计时、菜单隐藏暂停和拾取后同步清除规则均沿用。提示无独立按钮或输入拦截，不改变自动拾取、库存、来源凭证或自动换装规则。

## 运行证据

当前传奇／神器纹饰版见[纹饰运行截图](../../source-art/ui/equipment-notice-ornaments/README.md)。此前已获用户确认的布局与基础属性版见[属性版截图留档](../../source-art/ui/equipment-notice-stats/README.md)；对齐迭代保留在[原截图留档](../../source-art/ui/equipment-notice-unified-v2/README.md)，原始生命周期测量存于 `test-results/equipment-notice-unified-v2/`。

纹饰版类型检查与 Web 导出通过；844×390 和 932×430 实际游戏呈现复查通过。检查了传奇／神器的获得与掉落两种状态、法杖与弓的不同轮廓，以及普通、稀有、史诗不添加纹饰。装饰保持在通知边框内并置于装备图下方，名称左界仍为 94、属性列左界仍为 212，运行无页面异常。证据见 `src/cocos/release/equipment-notice-ornaments-validation.json`，TapTap 真机另行验收。

属性版已通过类型检查和 Web 导出，在 844×390、932×430 与 1280×720 复查。直接运行既有详情页计算并核对护胸护甲 +6%、传奇 Lv1 的威力 +6%／力量 +1、Lv40 的 +157.3%／+5，以及神器 Lv40 的 +166.7%／+5；数值完整显示，没有省略号。当前提示随夹具等级变化刷新，累计展示时长保持不变。另核对了类型／等级回退、数量后缀保留、容量不足短提示及窄提示收起属性列；运行无页面异常。记录见 `src/cocos/release/equipment-notice-stats-validation.json`。属性版截图中的测试角色为 Lv40，不作为用户当前旅程的数值记录。

随后名称单独左移 4 逻辑像素的修订再次通过类型检查和 Web 导出，在实际游戏获得／掉落两类提示中测得名称左界 94、品质及状态左界 98、属性列左界 212。当前截图与 `src/cocos/release/equipment-notice-name-offset-validation.json` 对应，属性数值和字号保持一致。

同日按用户对照原稿的反馈，将误用的三行居中修正为共同左对齐，并把正文起点从 88 移到 84 逻辑像素。原稿的品质、装备名和拾取提示均共用左边界，不应随每行文字长度各自居中。左对齐修订的运行证据单独保存在 `test-results/equipment-notice-left-alignment/`，此前居中截图保留于上述留档目录的 `before-left-alignment/`。

左对齐修订已通过类型检查与日常 `concept-2d` Web 导出；在实际游戏中复查了获得稀有装备、传奇掉落、史诗掉落与 932×430 大屏横屏。三行正文测得同一 84 逻辑像素左界，字号仍为 11.5／20／11，自动条间距仍为 8 逻辑像素，运行无页面异常。记录见 `src/cocos/release/equipment-notice-left-alignment-validation.json`。

`npm run check` 和 Cocos Web 导出通过。844×390、932×430 与 1280×720 实际场景复查通过，满技能状态下装备框、人物与主要操作区域分离；两类提示共用 300×72 逻辑尺寸，自动条下方间距为 8 逻辑像素。额外核对了数量、长名称省略、默认公共面板不变、提示无输入拦截、菜单隐藏不计时、23.9 秒仍显示、超过 24 秒只收起顶部、靠近自动拾取后不重弹及队列撤回。运行无页面或控制台错误。

568×320 旧小屏补充检查中，文字可读并按需省略，但提示与拥挤的小地图区域仍有重叠，该规格未作为布局通过项。默认 iPhone 14 及以上横屏范围不受此项影响，后续小屏 HUD 适配需同时整理小地图与操作区。

浏览器中的隔离旅程夹具仅用于真实 Cocos 场景的呈现及提示生命周期检查，不作为随机掉落、奖励来源或成长经济的验收。TapTap 目标真机触控、安全区和性能需另行验证。

# 开发与打包规范

2026-11-15 起生效，适用于 `src/cocos/` 的 TapTap 小游戏工程。开发入口为 [singularity-development](../../.agents/skills/singularity-development/SKILL.md)，界面任务同时遵守 [singularity-ui-design](../../.agents/skills/singularity-ui-design/SKILL.md)。

## 三种玩法档位

| 档位 | 用途与选择条件 | 机制 |
| --- | --- | --- |
| `dev` | 指定开发包或要求用加速机制快速跑通流程时 | 自动升至80级（2026-11-17用户确认）、技能采用正常冷却、怪物经验 ×5、关闭每日经验获取限制、Boss 分别保底结算传奇与神器；本次明确指定的覆盖项优先 |
| `test` | 正常测试包；未指定类型时的默认值 | 新旅程从1级开始，正常技能冷却、正常经验倍率、正常每日经验限制及其他正常玩法规则；HTML参数不自动升满级 |
| `release` | 用于正式发布；只有用户明确说明 release／正式发布包时制作 | 正常玩法规则，关闭开发覆盖和游客绕过，并附从上一正式发布版本到当前版本的 release 更新日志 |

“打包”“测试一下”“给我一个最新包”默认生成 test。处于开发阶段不自动选择 dev；要在包中启用 5 倍怪物经验或取消日限额来跑流程，选择 dev，并明确记录实际覆盖项。用户临时指定其他倍率或开关时只影响该次 dev，不修改长期默认值。

只有明确的 release／正式发布包请求才能选择 release。AppID 完整、版本号递增、测试通过、输出目录名称或旧脚本默认行为都不能代替该指令；本次指定 release 也不将以后的默认值改为 release。已明确要求时无需再次确认打包。制作 release 包不自动执行上传、提审、公开发布或 Git 提交／推送。

## 机制隔离

本地网页使用相同的编译档位：`npm start dev` 启动 7470 开发网页，`npm start test` 或无参数 `npm start` 启动 7469 正常测试网页，也可使用 `npm run start:dev` / `npm run start:test`。两个输出目录独立，复用原有公共配置和 dev 存储前缀；源码／资源变化或编译标记不匹配时重建，缓存可复用时直接启动。网页构建不分配新版本，dev 结束后恢复编辑器 test 配置。启动过程核对已占用端口对应的网页目录和档位，避免连到另一服务；`-Port` 可显式更换端口。浏览器仍为 preview 登录方式，档位与登录方式分开记录。

- 加速覆盖由统一的构建配置提供，仅 dev 生效；不能临时修改普通技能表、怪物经验表或正式限额再靠手动改回。共享玩法代码读取配置，避免在多个技能、怪物或奖励分支中散落判断。
- dev 默认覆盖包括怪物经验倍率、每日经验限制和 Boss 高级掉落，技能保持正常冷却；普攻节奏、伤害、资源消耗、解锁、剧情条件及非 Boss 掉落继续走正常规则，除非当次明确要求改变。2026-11-16 起，按用户确认的固定技能栏与短冷却规则，dev 不再清零技能冷却。
- “每日经验不限”须覆盖实际存在的每日经验门槛，不能只隐藏额度 UI；怪物经验 ×5 作用于真实奖励结算，不能只改飘字或任务经验。配置值、界面反馈和实际结果须一致。
- test / release 不包含可被 URL、浏览器缓存、旧 dev 存档或普通运行时开关重新启用的开发覆盖。检查正常冷却、单次经验和达到日限额后的行为；不能只核对包名或布尔值。
- dev 的存档、云端记录和排行榜等数据与正常环境隔离，不污染 test / release；优先用现有存储适配层及命名空间，不删除或覆盖既有正常进度。
- `audit` 和 Web 预览是验证方式，不是第四、第五种玩法档位。游客是单独的登录方式，不等于 dev；现有游客开关只用于专门的 test 包，普通 test 保留正常平台登录，dev 不自动绕过登录。

## 版本与产物

- 根 `package.json.version` 是唯一版本来源。沿用现有打包入口：每次实际打包 patch +1，同次调用内部重试不重复递增，Web 预览不递增。dev / test / release 共用一直递增的版本序列，失败不回退；不因创建文档、准备日志或 `-ValidateOnly` 校验而递增版本。
- 平台身份维护在 `src/cocos/release/taptap-project.json`；资源与分包复用 `release/taptap.json`、统一入口 `tools/build-taptap.cjs` 及现有官方转换工具（`Build-TapTap.ps1` 仅转发兼容）。不手改生成的运行版本或平台配置。
- 交付统一为 `src/out/<版本号>/SwordAndFire_<版本号>.zip`，不增加日期、任务或档位后缀。dev / test / release 在编译配置、包内 `release-info.json` 与包旁清单中区分；dev 另记录实际加速开关与倍率。内部记录应包含版本、构建时间、源码提交及必要的工作区内容快照、登录方式、ZIP 与 SHA-256、验证结果及待办。
- 版本号仍为三段整数，不以拼接 `-dev` / `-test` 替代平台版本；档位单独记录。现有 `guest-test` / `audit` 等包名用于既有登录或审计变体，不表示新增玩法档位。
- 完整上传 ZIP、首包、可玩前资源量分别记录；本地审计量与平台实际限制分开。改动包内容后必须重新生成相关报告与校验值，不能沿用旧哈希。
- 已有类型检查、规则检查、分包校验与手动验证优先复用；按本次变更检查档位和机制，不默认新增测试代码或依赖。
- 本地导出、官方转换、Web 运行和 TapTap 平台／真机验收分别登记；未上传或尚未完成的平台检查如实标记。

## release 更新日志

这里的 release 日志指版本更新说明，不是构建控制台输出。

每次 release 打包都要整理“上一次已正式发布的 release → 本次打包内容”的变化，覆盖两次正式发布之间经历的 dev / test 版本。不能只取最近一次测试包、相邻提交或本次聊天的修改。`lastSubmittedVersion` 或 `-PreviousVersion` 仅能提供相应的版本校验信息，不能单凭它们认定某个版本已经上线或确定源码差异。

1. 从已确认的发布记录、release 日志、标签、提交或产物清单确定上一正式发布的版本及内容基线。结合 Git 差异、工作区改动和资源／构建清单整理本次实际交付内容，不要求为了打包擅自提交代码。
2. 按玩家可理解的功能、调整、修复，以及必要的兼容／存档变化归纳，合并重复记录，剔除已撤销或未进入本次包的内容。不把开发加速写成正式玩法，也不把计划或未验收内容写成完成。
3. 写明本次版本、日期、对比基线、源码／产物范围、更新内容、验证结果和已知问题。首次正式发布标注“首次发布”，说明本次实际范围；确有上一版本但内容基线缺失时列出缺口并补齐，不能伪造完整差异。
4. 归档到 `docs/releases/<当前版本>.md`，并在本次 release 交付目录附同内容的 `RELEASE_NOTES.md`，与 ZIP、报告和校验文件一起交付。不能只在聊天中口述或拿构建日志替代；打包失败时只能记为草稿，不能记作已发布。
5. 本地 release 包完成与线上发布是不同状态。没有实际发布证据时，不推进“上一次已发布版本”的基线，不写“已上线”。

日志采用以下内容结构，按实际变化省略空类别；没有对应变化时不要填虚构条目：

```markdown
# <当前版本> release 更新日志

日期：<本次打包日期>
状态：<本地 release 包／已发布，按证据填写>
对比：<上一正式发布版本及提交／清单> → <当前版本及提交／工作区清单>

## 更新内容

- <新增、调整和修复，说明实际效果>

## 兼容与存档

- <需要用户知晓的兼容或存档变化>

## 验证与已知问题

- <已完成检查及其范围>
- <平台／真机待验证项和已知限制>
```

## 打包入口与实现

以下入口已接入，均复用现有 Cocos 导出、官方转换与包体验证；`build:tap` 和脚本无参数调用均默认 test。

| 命令 | 实际行为 |
| --- | --- |
| `npm run pack:taptap` | 默认正常 test 包、真实 AppID、正常平台登录 |
| `npm run pack:taptap:dev` | dev 独立存储、正常技能冷却、怪物经验 ×5、每日经验不限、Boss 传奇与神器分别保底 |
| `npm run pack:taptap:test` | 显式正常 test 包 |
| `npm run pack:taptap:release` | 显式 release，自动生成并携带正式版本更新日志 |
| `npm run pack:taptap:guest` | 独立游客 test 包，普通 test 不自动使用 |
| `npm run build:tap:audit` | 正常 test 规则、无身份本地审计 |
| `npm run build:tap:preview` | 正常 test 规则的 Web 预览，不升版 |

统一 Node 脚本使用 `--mode dev|test|release`（兼容入口使用 `-Profile dev|test|release`），默认 `test`；旧 `-TestPackage` 只作为 test 别名。`-GuestTest` 不允许与 dev、release、audit 或 Web 预览混用；audit 只使用 test。`--check`（兼容 `-ValidateOnly`）可核对档位和路径，不分配版本、不调用引擎、不生成上传包。

档位生成到 `assets/scripts/shared/BuildProfile.ts`，业务只读取编译后的只读配置。实际导出的 JS 必须包含唯一且匹配的档位标记，转换和报告均检查；不能把旧 test 导出改名为 dev。dev 存储在现有 `PlatformServices` 层统一加 `singularity.dev.` 前缀，所有读、写、删、枚举均隔离；目前无云存档或排行榜接入。dev / release 打包结束或失败后恢复工作区的 test 配置，避免影响后续编辑器预览。

dev 同样保留技能冷却、动作、资源与命中规则；不移除被动、装备触发或敌人冷却。怪物倍率在统一经验入口结算，涵盖狩猎、普通怪、首领和延迟结算的怪物奖励，不放大任务／档案经验。每日经验不限在实际奖励入口跳过共享限额、挂机子限额及其衰减，仍保留满级上限；HUD 显示 DEV 经验不限。

Boss 保底仅 dev 启用：每次有效击杀分别结算一件传奇和一件神器，复用章节、职业装备池与真实地面拾取。优先未拥有的装备，唯一装备已集齐／数量已满时沿用金币、铁的重复补偿，不复制唯一装备。首次与复战均生效，同一击杀不重复领奖，复战仍等待正常间隔；凭证归档与存读档完整校验，旧 dev 的正常随机记录继续可读。test / release 保留正常概率和保底，拒绝强制掉落凭证。

编译标记包含档位与规则摘要；倍率或开关变更后必须重新 Cocos 导出，旧版 dev 的导出不能只修改清单或文件名冒充新规则。

## 更新条目与正式发布基线

- 完成实际新增、调整、修复、兼容／存档或已知问题记录时，在 `src/cocos/release/changes.json` 追加唯一 `id`、`category` 与 `summary`。只写当前实际实现的行为；已发布条目不改写，后续修正使用新 ID。打包流程不需要再手工复制更新内容。
- `tools/release-notes.cjs` 从 `release/published-release.json` 查找上一已登记正式版本，并校验其源码清单。未发布过且项目明确记录 `publiclyReleased: false` 时生成首次发布日志；若已有发布但基线缺失或损坏则停止，不能取最近 test／dev 或 `lastSubmittedVersion` 代替。
- 自动汇总上一正式清单未包含的更新条目，以及构建输入的新增、修改、删除与 SHA-256 差异。包括暂存、未暂存和未跟踪但未被忽略的源码／资源；不依赖先提交 Git。使用 Git 枚举与 Node 内置文件／哈希能力，无新增运行依赖。源码差异不能单独推断玩家效果，缺少语义条目时如实标注。
- 导出前生成日志、`source-manifest.json` 和 `release-changes.json`；导出后复核输入未变化，再纳入官方 ZIP。包体检查通过后同时复制到交付目录，日志归档到 `docs/releases/<版本>.md`。ZIP CRC、清单一致性与哈希继续检查，失败不归档成功日志。
- 制作候选包不会修改发布基线。**实际正式上线后**，在已授权记录发布结果的任务中执行 `npm run release:tap:record -- <已发布包的交付目录>`，核对交付 ZIP 哈希及其内嵌说明／清单后保存正式清单。只记录已上线的 release，拒绝 test、dev、旧版本、损坏包或不一致的旁置文件；该命令不上传、不提审、不公开发布。

命名示例中的时间以 UTC 为准，日志日期使用 Asia/Shanghai。版本始终取仓库根版本；不可通过手改包名、清单或日志把低版本升级或改变档位。

## dev 手动快速验证工具

暂停页和设置 → 旅途页提供“DEV 快速验证”，复用公共暗金列表面板，不新增常驻 HUD 按钮。仅 dev 开放入口和执行权限；test / release 即使收到相同命令也不修改状态。开局不自动使用这些工具，仍从当前独立 dev 存档继续。

| 手动操作 | 验证用途 | 边界 |
| --- | --- | --- |
| 补满生命与职业资源 | 连续观察技能、命中和受击效果 | 只补当前数值，保留后续伤害、技能消耗、药水冷却；死亡仍用正常重试 |
| 补齐药水 | 验证四类药品与快捷栏 | 补至各自真实携带上限 |
| 补充金币与锻造材料 | 验证强化、锻造和传承流程 | 金币、铁、符文、核心各补至 9999；仍按正常规则消耗与检查图纸、场地 |
| 等级＋5／升至80级 | 验证成长阶段、技能与属性配置 | 通过正常经验／成长入口推进，不倒退、不重复加点，不改剧情、任务或装备来源 |
| 清除 Boss 再战等待 | 连续检查战斗、掉落与拾取 | 只清除已有等待，从旅程页重新挑战，仍须真实击杀，不重复结算旧尸体 |

技能效果直接复用已有训练场：1—5 级技能、单靶／靶阵／群怪、资源模式与伤害统计均在隔离练习会话中进行，退出返回原旅程。无敌、自动无限资源、自动完成任务及全场景解锁不属于本次默认加速。

本地 Web 导出与 TapTap 导出共用项目构建锁；正在构建时，第二个入口在准备配置与分配版本前拒绝启动，避免普通预览将 dev 配置覆盖为 test。档位标记复核仍保留，发现旧档位或混合导出时停止，不交付错误标记的包。

2026-11-17 的80级成长修订：正常新旅程从1级起步，dev自动80级；八章各约10级。按用户要求不实现旧成长存档迁移，使用新规则创建和验证存档。具体经验、属性、技能点与章节战斗预算见 `assets/scripts/features/progression/data/CampaignProgression.ts`（位于 `src/cocos/`）。

三个月成长规则采用独立 `sword-fire.campaign90-v1` 存档：八章按约90自然日／77活跃日、每次30–45分钟规划，主线与必经首通约60%，常规探索约30%，自由战斗约10%；额外唯一探索可替代自由战斗，不设日期、在线时长或连续登录解锁门槛。仅前两章已有真实奖励来源，后六章预算与内容工时仍为未开放规划；实际时长及装备材料验收见 `docs/design/campaign-three-month-v1.json`。

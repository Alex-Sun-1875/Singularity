# HUD 圆弧与补给对齐

2026-11-10，Cocos Creator 3.8.8 / TypeScript，面向 TapTap 小游戏横屏 HUD。

长期约束见[界面布局设计规范](../design/ui-layout-guidelines.md)：正常探索和战斗时，HUD不得遮挡游戏的主要区域。本页只记录这一版实现与验证，不以占用面积减少代替主区域无遮挡的验收。

后续已改为四个固定主技能槽、流派独立配置及小地图圆边入口，最新实现见[四流派技能槽与小地图入口](../design/combat-loadouts-v1.md)。下文为v23阶段记录。

复用现有 Cocos Node、UITransform、Button 和已有金属皮肤，无新增依赖或测试套件。主技能取消逐个手写偏移，以攻击键为圆心，在 108° 圆弧上按技能数量等分角度；半径根据触控直径与间距计算。闪避和辅助技能排列为统一间距的最多两行网格。圆按钮保留引擎原有视口及遮罩命中检查，再限制到圆形触控区，避免斜向排列的矩形角落抢走相邻技能的触控。

生命药与火油作为补给面板的子节点，左右等距、同一基线；补给面板优先在屏幕底边居中，短屏空间不足时整体限制在摇杆与战斗按钮之间。移除额外的补给标题和多余留白，检查点按钮缩窄并移到补给上方。手机技能可见直径约44px，触控直径保持至少48px，独立触控目标保留至少8px间距。

同时修复界面重建时通过同名查找取得待销毁旧闪避节点的问题，改为持有当前节点引用。

验证复用现有浏览器检查流程，覆盖915×412、667×375、568×320、1280×720，以及剑、弓、法杖、满技能、三主技能、辅助技能和空槽等九种配置，共36个布局。检查同半径、等角距、面板居中、屏幕边界、圆形触控间距及地图/设置入口，均通过，无浏览器运行错误。满技能战斗按钮包围面积相对上一版分别缩小13.1%、5.0%、4.3%、30.9%；这些数字只表示战斗控件包围矩形，不代表整屏遮挡率。

类型检查与全新输出目录的 web-mobile 构建通过，完整构建同步到默认7469试玩。现有触控流程确认双指移动与攻击、火油取消、拉弓取消不发箭及取消后闪避。复用触控脚本时先跳过开场演出，使输入处于正常游戏状态；未修改演出规则。

# 当前3D角色制作

用户要求倾斜俯视的真实3D场景、实体角色和动作，并明确本地开发不需要云端模型生成。模型以v5造型为准，在本地制作、适配和导入。头像棋子画面被否决，不计为可交付版本。

## 资源真源

- 主角：`assets/concepts/revision-v5/hero-v5-balanced.png`。
- 弥菈：`assets/concepts/revision-v5/explorers-v5-recast.png`左一人物。
- 其他核心同伴与对手沿用当前v5人物板。
- 本地尚无这批人物对应的已验收骨骼模型。旧blockout与角色研究不作回退。

## 制作顺序

1. 以本地v5人物板为造型依据，不需要登录、Token或云端绑定。
2. 在本地3D制作流程中完成实体网格和材质。主角保留棕色卷发、墨绿短披肩、棕色皮革与单侧钢肩甲；现有设定图不能直接作为3D角色使用。
3. 制作或适配骨骼及待机、跑动、攻击、受击动作；检查关节变形、脚底接触和武器握持。如果使用基础模型或动作，记录其来源和使用许可。
4. 保留可编辑源文件，导出引擎可用的完整骨骼模型与动作；运行资源落入`src/assets/model/`。
5. 导入引擎，实际检查比例、朝向、骨骼、材质、脚底高度与碰撞。
6. 接入待机、移动、攻击与受击动作；通过多帧实际渲染判断动作与命中时机，不能以单帧或静态模型位移冒充动画。

## 当前状态

云端模型生成请求从未提交，当前已停用这条路线，不再等待Maker登录或绑定。当前实际缺口是v5人物的实体网格、骨骼和动作；本地最新人物文件仍只有设定图。接下来解决这些本地资产与导入问题，而不是让用户创建Token。

已用隔离GLB探针核实，本机Runtime的Model资源接口不能直接读取该GLB；错误为`triangle.glb is not a valid model file`。继续使用UrhoX时，要完成本地原生骨骼网格与动作的转换，加载`.mdl`和实际材质/动作资源。不得将单独GLB或仅有静态转换结果冒称已经完成骨骼导入。

本地开发套件的`blend_to_urhox.py`明确对Armature只导出求值后的静态网格，会丢失骨骼动作；不可用它把人物“转成功”后就宣称可动画。最终交付必须实际检查骨骼数量、动画轨道和多帧渲染。

角色加载器已支持经过核实的`.prefab`，或`.mdl`加按序材质列表；真实Runtime已验证原生格式加载。网格可以先用于检查，但只有骨骼与待机/跑动/攻击/受击资源全部齐备，才允许启程。当前尚无v5实体模型和动作。

真实3D环境的地形、道路、旅店、石墙、植被和交互道具已开始制作，不能视为最终地图美术或完整3D可玩交付。

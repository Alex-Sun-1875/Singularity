The local Cocos asset pipeline starts from the current skinned `raphael.blend`,
`mira.blend`, and `raider.blend`; it does not alter these legacy files. Editable
derivatives are in `source-art/characters/cocos/<id>.blend`. The generated game

loads each of the ten character folders as a Cocos AssetBundle named
`actor-<id>` (folder bundle priority 9), using
`assetManager.loadBundle('actor-' + id)` and then the prefab subasset address
`<id>/<id>` inside that bundle. This bundle loading route is verified in the
running Cocos preview; FBX/PNG paths and their `.meta` UUIDs have not moved.
The older global resource address `actors/<id>/<id>/<id>` remains recorded in
the asset manifests as an archive reference, not the current runtime loader.
Standalone props remain at their ordinary `resources` addresses below.

The 2026-11-04 runtime material pass replaces imported FBX shading with standard

## Motion mapping

Every character contains these actual baked FBX actions: `idle`, `run`,
`attack_sword`, `attack_bow`, `attack_staff`, `spell`, `dodge`, `hit`, `death`,
and `interact`. The exporter samples at 30 fps without key simplification.
The Blender FBX importer prefixes the names as `<id>|<id>|<clip>`; consumers
should use the suffix after the last `|`. Durations, loop intent and the death
final-pose hold are recorded in each `manifest.json`.

Idle and run loop. The other actions play once. Run stays in place; dodge
returns to its original root position. Death falls forward and holds the last
28% of the clip. Attack motions use separate hand targets for sword, bow,
staff, and spell rather than aliases of one attack. The FBX axis settings are
positive Z forward and positive Y up, with metre units. Blender reimports the
files into its native Z-up coordinate system for inspection.
The earlier export used a 180-degree Y rotation on the model child. This is
historical: the current library exports already face `+Z` and use model Y 0,
as verified by the current mobile and NPC evidence above.

Dodge and death root height is corrected from evaluated boot geometry. Death
uses a horizontal final fall without the former leg bend that pushed a foot
below the floor. All source samples retain their original clip ranges and a
minimum foot height of approximately +1mm. The final LoD roundtrip records
the independent 21-sample ground audit in each `inspection.json`.

It must not be used to overwrite the current UAL library integration. The
current localized adapters are `cocos_fix_hero_grip.py -- --production` and
`cocos_library_weapons.py -- --production --weapon bow`; they work on the
existing saved sources and reuse the existing mature assets.

```powershell
& src/.tools/blender-4.5.15-windows-x64/blender.exe --background --factory-startup --python tools/model-pipeline/cocos_verify_characters.py -- --render --runtime
```

Each Blender script accepts `-- --character raphael` to work on one identity.
The verifier reopens the exported FBX, checks deformed vertices across actions,
bone names, texture resolution, height, ground contact and the held death pose.
It writes `inspection.json` beside each FBX. Blender 4.5 requires explicitly
selecting an action slot when switching between reimported FBX actions; the
verifier does this. Rendered front/back/side comparisons and the hero motion
contact sheet are saved under `source-art/characters/cocos/previews/runtime`.
These render the actual reimported LoD FBX and compact game maps. The camera
moves to obtain front/back/side views, so imported object animation cannot
override the requested viewpoint. Source comparisons remain in `previews`.

The full-resolution authoring maps are preserved under
`source-art/characters/cocos/textures/<id>`. Export maps use 1024px skin and
512px eyes/brows for Raphael and Mira, 512px skin and 256px eyes/brows for the
eight supporting characters, and 256px wardrobe maps. PNGs use maximum
compression; low-visibility procedural grain is quantized to reduce entropy.
Source mesh geometry remains intact. Export-only LoD targets 65k triangles
for Raphael, 60k for Mira, and 42k for each supporting character. A 0.001
FBX simplification threshold removes constant-channel redundancy after 30fps
sampling. Exact byte and triangle totals are in `optimization-report.json`.

## Source and current visual limits

The MakeHuman basemesh, game-engine rig, skin maps, eyes, eyebrows, suit and
boots were already installed locally. The relevant `.mhclo` and `.mhmat`
headers explicitly record their September 2020 CC0 release. Recorded original
copyright holders are Data Collection AB, Joel Palmius, and Jonas Hauquier.
The pinned MPFB and CC0 system asset archives are downloaded by the local setup
script when missing. No cloud model generation is part of this pipeline.
The new wardrobe, hair geometry, props, local maps and motions are editable
local authoring work. See `resources/actors/LICENSE.txt` for the source record.

These are game character approximations directed by the v5 reference sheets.
They do **not** reproduce the reference's photoreal skin, bespoke facial
sculpting, layered leather engraving, natural groom, fabric folds, or expertly
authored combat animation. Procedural wave/curl tubes remain visibly stylized
at close range. Cloaks have skeletal deformation rather than cloth simulation.
Neutral comparisons hide equipped hand meshes; the hero motion contact sheet
shows the hand-mounted sword. The neutral renders are review evidence, not proof of reference
matching. Triangle and material budgets are recorded for further optimization.

Review boards `previews/runtime/raphael-v5-runtime-comparison.png` and
`mira-v5-runtime-comparison.png` place the unchanged original concept sheet
beside actual LoD FBX front/back/side and face detail. The reference SHA256
is recorded in `comparison-record.json`; the original sheets are not edited.

The current FBX files reference their sibling game PNGs and do not embed
`Video.Content`. External PNG deduplication/moving is deferred: a clean import
still requires those siblings. A later packaging change must first embed the
images or preserve resolvable references, verify an isolated import, and retain
existing model/resource paths and `.meta` UUIDs.

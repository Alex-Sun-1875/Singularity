## 视觉结论

采用**细节丰富、材质可信的写实手绘 2.5D**。以已获批的 [角色方向图](../../assets/concepts/character-direction-v1.png) 为主要验收依据，而不是以旧占位模型为外观基准。参考《博德之门 3》的只是成人比例、功能性装备、皮革金属布料层次；不复刻其中人物、脸、装备套装、徽章、界面或提取其资源。

旧版记录有 6 张参考图。原主角的青绿披布、皮带、非对称肩甲、米色卷袖、油壶和长剑仍是材质与读形参考；旧佣兵图的锈红内衬、铁帽、短棍和圆盾也可保留。**这些旧图没有因为本轮更名就自动成为新人物、行会或骑士团的定稿。** 首章旧环境图仅参考暖灰石、旧木与营火，不照搬复杂悬崖全景、塔楼数量或摆设。

[旧配角方向参考](../../assets/concepts/supporting-cast-direction-v1.png) 原标阿禾、老周、罗铎，内部资源ID仍对应艾妲、布兰、洛德里克。它未获用户单独批准，也不是模型或已配准游戏素材。新身份要复核：艾妲是佩契约牌的旅行经纪人，不是管粮村民；布兰围裙边保留一枚旧工役徽记；洛德里克的蓝灰披风与方盾表达正规堡卫，不加骷髅或王冠。新服饰细节属于同一角色设计的修订，不增加角色数量，但必须重新出状态图与方向一致性证据。

### 既有探宝章节的视觉记录

- **佣兵契约**只负责把玩家送向第一座宝匣：公告上的简图、银枝蜡封和报酬栏可一眼读懂，不把委托人做成长时间宣读规则的官员。纹章为纸张/布旗材质变体，不新建阵营人物。
- **旧骑士团遗址**用凿痕、断拱、护具陈列槽和同源鹿角刻纹表达藏宝来源。短金光表明真品与旧石刻同源；不是钥匙、诅咒、控制城门或世界末日机关。
- **沉钟秘藏**在被征用的河湾礼拜堂后侧货台；箱、卷筒、器物三种轮廓提示宝物和线索，而不是三堆补给。箱盖铜纹与锈蚀、未被触动的内衬形成发现感，不靠满屏金光。
- **灰石堡宝库**位于现有门台后的下层军械区，Boss败后拉开库房栅门，露出原主箱2—3m深的局部宝龛，保持奖励来源；这不是区域v2的面积上限。区域中的外堡、聚落、室内与荒野需形成独立可探索空间，新增建筑/室内母件另核，不用该库门代替整座区域。
- **古物与训练取舍**用守誓护符完整外圈与余烬铜芯拆出的内芯两个近景图，说明同一装配件只能保留一种；另一种明确变为“本次未获得”。取舍解锁守誓护符或余烬铜芯传承训练，不是48类物品中的项链/符咒；1训练槽与9槽合法永久装备/套装可并存；2符咒快捷栏只引用库存，不计套数，不能把训练上限套到所有装备。符咒/法杖的可用魔法与古物本身的同源反光分开，不新建同伴分支。
- **Boss爆装反馈**：退出战斗姿态→宝匣/装备短双环亮起→物品名和已获状态→一行数值变化。四章至少有一次固定装备或改装奖励；主线不以随机概率决定是否值得打。装备页中48类物品逐件有独立轮廓：近战、弓、杖、副手、四部位护甲、戒指/项链、符咒都能从结构辨认，不只靠品质变色。战斗中至少能辨武器家族和四构筑，不得把弓杖仍画成统一单手剑；逐件附件和护甲混搭输出须经样板单独估算。

后来的主角四视图、佣兵和头目细节图继续只作材质研究；跨角度装备位置、比例、相机仍需校准。不能切开就声称获得可用四向游戏素材。

## 不能退回的质量底线

- 自然成年人体比例，约 7—7.5 头身作为绘制检查辅助；肩、肘、膝和脚踝不能是拼接圆柱或方块。非写实夸张只用于读形，不将头放大成卡通比例。
- 布料在肩带和关节处有受力褶，皮革有厚度、缝线和磨损方向，钢板有厚薄和局部高光。粗糙度有变化，不是每块材料一片纯色。
- 面数不是验收指标。平滑法线、增加细分、随机噪点都不能代替解剖、衣装结构和材质设计。
- 在实际屏幕尺寸下，先看得出武器、盾形、朝向和动作，再看得到细节。不要把所有衣褶、铆钉画成同等强的白色轮廓。
- 无强烈血腥、肢解或死亡特写；倒地是退出战斗，洛德里克结局明确缴械投降。

## 推荐生产路线

**选择的生产提案：可编辑高质量源资产 → 固定镜头渲染/修绘 → 注册后的 2.5D 透明动作精灵。** 这是待样板验证的方案，不是“已成功完成此管线”的事实。

| 层 | 交付 | 验收与用途 |
| --- | --- | --- |
| 设计层 | 原创形体、服装结构、正背与侧面一致性参考 | 决定长什么样，不直接充当游戏动画 |
| 源资产层 | `.blend`、原创贴图源文件、骨架与动作；需要交换时另导出 `.glb` | 能编辑、换动作、重渲染；GLB 导出成功不等于皮肤变形正确 |
| 游戏图像层 | 透明 PNG 动作序列、分图集 PNG、逐帧描述 JSON 的规格 | 固定镜头、脚底锚点、时序和事件注册；后续实现，不在本轮生成 |
| 展示层 | 100% 原尺寸、1280×720 和 1920×1080 合成检查图 | 与获批图对照；查看实际缩小可读性和遮挡 |

源角色建议从 30k—80k 三角面的可变形主体试制，局部雕刻可更高；不将此范围当最终风格保证或运行端预算。源材质通常 2K，只有样板确实需要才提高；运行端不随身携带全部源贴图。衣服关节、手、武器握持与盾牌接口先通过绑定测试，再批量渲染。

直接绘制精灵是备选：若源模型达不到所选质感，可用统一结构稿逐帧绘制，但仍必须满足方向一致、锚点、时序和预算。不以逐帧独立生成且未校准的图片替代动作管线。实时 3D 是另一条待重新评估的路线，不与当前精灵内存预算混算；没有在本轮选择或完成引擎安装、3D 渲染接入。

## 镜头与像素约定

- 固定正交镜头为主；相机仰角起点 **32°**，四方向方位起点 **45°、135°、225°、315°**，延续已有占位的坐标约定。样板可一次校正角度，锁定后全库重用。
- 源坐标：米制，Blender Z 向上、角色正面 `-Y`；GLB 使用 Y 向上。地面根节点为原点，武器握点另登记，不靠网格包围盒底部猜脚底。
- 逻辑构图基准 1280×720 横屏，1920×1080 同构图放大检查；常规人物在基准视口目标高 100—132 px，头目 118—150 px。不是画满半屏的立绘；也不把人物缩到几十像素后要求看清全部铆钉。
- 工作母帧 512×512；特别宽的挥击可 768×512，但保持像素/米和锚点不变。运行候选普通人物 192 或 256 方形未裁母框、头目 256 方形；正式尺寸由样板比较确定，不盲目把所有动作发成 512。
- 道具小件候选 128/256，车、门、机械 512；地形模块最高 512—1024，较大建筑拆段，不导出一整章一张巨大画布。UI 图标母稿 256、候选输出 64/128。
- 遮挡分前景、脚部基底和可淡出上层。人物接近墙、树、门时仍须看见脚底和交互符号；不能用半透明整地图破坏层次。

## 内存与包体不能用 PNG 文件大小代替

以下仅以旧剑系主角每方向68帧、4向272帧为计算示例，不代表新系统总量，RGBA8 未压缩纹理的简单下界为 `帧数 × 宽 × 高 × 4 字节`：

| 未裁帧尺寸 | 272 帧理论像素数据 | 加完整 mip 链约乘 4/3 |
| --- | --- | --- |
| 192×192 | 38.25 MiB | 51 MiB |
| 256×256 | 68 MiB | 90.67 MiB |
| 512×512 | 272 MiB | 362.67 MiB |

这里尚未算图集留白、边距、解码副本、音频、游戏对象和临时渲染目标。透明像素在未裁图集中仍占内存；PNG 压得很小也不改变 RGBA8 大小。裁边后的平均帧若为 96×144，主角像素数据约 14.34 MiB，但这只是**需实际测量的裁边示例**，不是已有节省结果。图集必须计整页：1024×1024 RGBA8 是 4 MiB，2048×2048 是 16 MiB，不按有效像素自报更小。

旧剑系首章动作基线约920个四向帧（不含本轮弓/杖/符/换装增量），若全部用 256×256 同时常驻，仅像素数据就有 230 MiB，已经超过总体软目标。因此必须按安全营地、山路、头目场景分包，卸载不用的 NPC/头目动作，裁边和复用材质；不能在报告中把 920 帧都当成 33 张旧静态图那样廉价。多名灰披佣兵共享同一图集，不按实例数重复纹理，但仍增加绘制和动画成本。

| 内部起始预算 | 目标与约束 |
| --- | --- |
| 图集 | 优先 1024，必要时 2048；2—4 px 外扩边、帧间至少 4 px 空隙；每页独立列尺寸、字节、用途 |
| 角色图集常驻 | 约 48 MiB 软目标；主角加当前敌种，不一次预载全部11角色 |
| 场景／UI／VFX | 约 32／8／8 MiB 常驻软目标；合计纹理约 96 MiB |
| 总运行内存 | 暂以 200 MiB 软目标；含解码峰值，不能只看纹理 |
| 压缩下载 | 首次核心包约 10 MB、单章资源约 20 MB 起点；实测前不得声称达标 |
| 帧率与负荷 | 被否决v2曾以常规同时活跃8敌/峰12与30FPS为观察目标；v3并发/性能预算未定，非区域总实例上限或已达标结果；分块模拟与并发须实测；4片火区是常态性能预算，非逻辑上限；头目首验无增援 |
| 绘制 | 60 次左右绘制调用作为初始观察线，不是官方上限；批处理、透明叠层和遮挡需实测 |

火区常态预算不改伤害规则：桶连锁与投油形成第5片及更多有效火区时，每片实际伤害区域都必须完整可见；不得自动隐藏或删除第5片。可以减少装饰粒子、合批或合并重叠视觉层，但不能丢掉有效区域边界或改变生命周期。超过常态预算的连锁情形须单独测试。

装备/商人版204与更早148均作为基线追溯；区域v2新增地形、室内、地标、实例与实施成本按[资源登记](resource-register.md)另核，不能继续称204已覆盖当前全量。48类物品近景卡按类别/当前比较对象按需加载，关闭可回收，不一次预载全部高清卡与动作组合。新增项不会自动提高原内存软目标，原目标也不能据此宣称仍已达标；样板要加入Boss掉落、三宝藏点同屏、近景装备比较与终章小宝龛重测峰值。

固定缩放首测可不用 mip；若缩远抖动必须增加 mip 并重新计预算。运行格式、GPU 压缩、纹理上限与平台音频支持等待真实目标设备和实际运行环境验证；本文不编造 Tap 官方数值。

## 武器品质与合成的视觉边界

品质用文字、边框颜色与1—5个缺口共同表达；品质不替代装备阶级。所有装备卡同时标阶级、品质、槽位、基础属性、固定特性、套装归属和已解锁状态，比较卡只比较实际生效项，不以“更金、更大”暗示一定更强。五品质共享一套边框状态，不为每档加新特效或整套宝箱。

合成界面必须看清输入、将消耗的材料和产出；制作前后分别保留预览态与已完成态，取消不扣料。分解预览与制作颜色/图标不同，禁止同位置立即把新武器拆掉。配方纸只复用纸张底稿与结果剑缩图，不按每条配方重复新增独立插图。

武器与护甲近景为逐件原创形体稿；物品目录48类、六套四件套与四构筑不等于48套完整角色动画。当前没有通过的新角色或动作。必须先做近战、弓、杖、符咒和四部位护甲的分层附件/遮挡样板，登记额外方向与动作输出、重测握点和内存；1720帧只能引用为旧剑系基线，不能冒称新系统全量已覆盖。

## 商人与地图的视觉边界

5位特色商人中只新增蕾萨、墨伦、娜薇3个原创成人角色，艾妲/布兰保留同人身份与旧资源来源；新角色不因为有名字就称已有成品。猎货/符印/灯油古物通过服装、工具与既有棚架陈列区分，不为每商店新增一套建筑模块。金币与商人标记各1个共用图标，交易页与四区域地图日志各1个界面；原四局部地图布局不能当成区域v2完整主图；四区域/地下分层制图、五静帧头像与库存/发现状态都是仍需制作的衍生输出，不重复加独立设计，也不免除工作量。

永久J首饰、W16法器与古物训练护符有完整边框/结构；8种一次性符咒加清楚的张数角标与耗去表现。地图不以未发现宝箱的全亮光点代替探索，商人头像不取未通过旧占位作正式肖像；最终可用状态要同时有文字和轮廓。

## 被否决v2的空间与性能记录

v2曾提出四章荒野/聚落/室内与20—40/35—60分钟，但用户仍否决其尺度和定位；这些不是v3的时间或空间预算。剧情、战斗与探索都应有独立作用，不能让美术与人物只围绕藏宝点布置；v3具体方案待研究。旧12area/12route/12cp仅保留主线与存档索引，不要求世界仍是12个小场景或每章三条孤立道路。本节边界/路径仅追溯[被否决区域尺度第二版](../maps/regional-scale-v2.md)，不是v3权威；其4包围盒也不是walk面积。

原6地形模块、49道具、11角色和13界面不是扩区全局上限；新候选母项、外观变体与重复实例分开计，环境遮挡、室内明暗、入口辨识、植被前后层、地图层级、角色/敌人导航、切区加载与状态恢复都要验证。旧纹理/200MiB/单屏敌人软目标只作样板观察线，不能按地图包围盒面积直接乘像素，也不能把未活跃分块当零成本；扩区常驻、切换峰值与包体预算尚未测。

# 任务追踪收展与导航变色实装

2026-11-11，按用户确认的v8设计及“保留状态切换变色”要求接入Cocos主工程。

## 实现

- `features/journey/runtime/QuestTracker.ts`负责任务框，`app/Hud.ts`组合与传入实际引导数据。复用Cocos Button、Label、公共DoubleGoldFrame及原版深色内衬，没有新增依赖或生成素材。
- 默认收起为35逻辑像素高的单行目标与距离；点击左侧任务区展开为56像素高的三行，再次点击收起。两态均与头像状态框等宽、同一左边界，不画展开／收起小箭头。上下辅助文字9.5、展开目标12.5、收起目标11，沿用确认后的字号层级。
- 右侧导航操作独立。收展回调只改变显示，不进入菜单、不修改自动操作状态、不暂停或开启寻路。长文本保存完整原文后分别省略，反复收展不丢失内容或累计截断；完整任务仍可从旅程页查看。
- 沿用`navigationFeedback`与公共颜色。运行时青色、暂停时琥珀色、抵达时金色、受阻时辅助灰，任务文字、距离和操作同步表达；默认目标与距离保留文字层级，地点保留任务色。收展不重置颜色，抵达仍不是任务完成。抵达和受阻保留原有按钮禁用逻辑。
- 屏幕尺寸变化后保留收展状态；冷启动默认收起。导航、任务和存档规则不变，没有新增平台存储或浏览器依赖。
- 手机导航触控区48×48，和左侧触控区保持8逻辑像素间隔。框体顶边距头像区16像素，为收起态补足触控高度留出间隔。摇杆按展开态最大占位预留空间；收起后的旧面板区域不残留输入拦截。

## 验证

`npm run check`、日常`npm run build`和`npm run check:tap -- --mode test`通过。实际`concept-2d`入口中验证：

- 触控出发→寻路，收展后继续寻路且颜色保留；手动接管→暂停，收展后仍暂停；点击继续→寻路；点击停止→手动状态。
- 使用引导数据夹具检查抵达和受阻的颜色及禁用状态，不将夹具冒充真实抵达或真实平台验收。
- 844×390、852×393、926×428、932×430、915×412、667×375横屏，1280×720桌面；另检查模拟左右44、底部21像素的安全区。手机操作触控区保持48×48、相邻间隔8，面板宽度跟随头像。
- 快速收展20次后直接子节点仍为7个，公共框加载完成；收起后原展开区域不再拦截场景操作。长文本反复收展后保留原文和既定字号。
- Web运行未捕获页面异常。没有新增测试用例、脚手架或测试依赖。

构建中遇到已有的Windows文件打开`UNKNOWN`错误；保留配置备份并写回相同字节后恢复，未修改引擎配置语义或降低帧率。测试包首次版本分配后同步中断，继续使用已分配的0.3.13恢复原打包流程，没有重复递增版本或放宽游客校验。

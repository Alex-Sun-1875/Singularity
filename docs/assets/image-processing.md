# 图像处理规范

适用于角色、序列帧、头像、装备、地图、UI 等位图素材。2026-11-08按用户最新要求，生图与生成式编辑默认改用云端 OpenAI image_gen；常规像素处理继续优先使用本地工具。

## 处理方式的选择

1. **复用现有素材与本地常规工具。** 裁切、缩放、旋转、透明通道处理、比例与锚点对齐、序列帧排版、遮罩合成，优先使用项目已有脚本、Pillow、OpenCV 或成熟组件。已有正确局部时优先复用这些像素。
2. **需要生成新像素时，默认使用云端 OpenAI image_gen。** 生图和生成式编辑沿用任务授权，不逐张重复确认。先检查代表小样再扩大批量；生成成功与美术合格分别记录。最终项目图保存到仓库，记录提示词、来源、尺寸、校验和验收状态。
3. **本地生成改为明确要求时使用。** 不默认启动Qwen或其他本地模型，也不自动回退本地。既有ComfyUI、模型和历史结果保留；明确使用本地推理时遵守下文缓存与下载规则。云端失败时如实记录限制，继续已有素材、设计和确定性本地处理。

云端输入限制为必要参考图、局部和遮罩；接口支持时复用文件引用。不能确认缓存行为时不声称同一参考图只上传一次。云端生成与视觉检查按实际方式说明，常规本地排版不能表述为整个聊天完全离线。

## 模型、依赖和运行环境下载

- **不得使用代理下载。** 范围包括权重、编码器、VAE、Python 包、插件、安装器和便携运行环境。普通直连下载不等同于代理流量，文件体积本身不是排除合适模型的理由。
- 下载前核实环境变量、系统代理、透明代理/TUN 和实际目标路由；仅清空代理环境变量或设置 `NO_PROXY` 不能作为已直连的充分证据。
- 当前复用 `F:\Models\deployment\Download-Direct.ps1`：curl 的 `-q` 忽略默认配置，`--proxy=` 和 `--noproxy '*'` 禁用代理，`--interface` 绑定已核实的物理网卡地址。该脚本当前默认地址为 `192.168.1.14`，地址变化时先重新确认路由，再通过 `-LocalAddress` 指定当前地址，不盲用旧值。
- 记录实际本地地址、远端地址、来源、文件大小与校验结果。直连失败时换可直连来源或保留断点暂停该项下载，不自动回退代理，不为下载而全局关闭或改写用户的代理配置。
- 优先官方来源；使用直连镜像时，按**同一仓库和精确文件路径**核对官方 SHA256 等校验值。不能因文件同名就混用其他仓库或版本的校验值。校验通过后复用缓存，避免重复下载。
- 安装与推理尽量使用已经备齐的本地文件；依赖管理器不得通过系统代理补包，缺失文件须按上述直连规则补齐。

### 模型驻留与空闲释放

用户于2026-11-07要求：用完不立即卸载，连续空闲10分钟才释放。任务完成后保留模型和执行缓存供后续任务复用；每次任务完成重新开始600秒计时，执行中或有排队任务时不触发空闲卸载。正常出图、检查、排版完成后不要主动调用 `/free`。到期复用引擎原生 `unload_all_models()`、执行缓存重置与垃圾/分配器缓存清理；保留服务进程和本地界面，下一次任务按需重新加载。推理时显存与CPU内存的正常调度仍由ComfyUI负责，不承诺整个模型始终驻留显存。

`F:\Models\Start-ComfyUI.ps1` 设置 `COMFYUI_MODEL_IDLE_SECONDS=600`。ComfyUI 0.44.0没有原生空闲卸载参数，使用 `F:\Models\deployment\configure_idle_unload.py` 为现有任务worker安装小型、可重复执行的适配：原位计时，并在现有队列RLock内确认执行及等待队列均为空后释放，避免外部 `/free` 轮询产生延迟旗标与新任务竞态。适配无需第三方节点或新依赖；启动时检查源码片段并记录 `F:\Models\deployment\idle-unload-config.json`，引擎升级导致片段不匹配时应审查适配，不静默套用旧修改。配置修改后已重启空闲服务使其生效。

模型、运行环境和大体积缓存保留在 `F:\Models`，不复制进游戏资源或 Git。提示词、工作流、来源、许可证、校验和小样记录保留在项目素材目录。各模型、变体和组件的许可须分别核实，当前 Qwen 模型许可说明见下文。

## 角色与序列帧验收

- 2026-11-08 用户重新指定本轮“图三挥剑（W01 attack phase0）”为外观权威，并指出腿的大小不一致。当前统一记录见 [attack-identity-v5](../../source-art/characters/2d-concepts/attack-identity-v5/README.md)。头脸、衣型、腰包、腿长/粗细及靴筒都须统一；大小腿应分别校准，不再仅用躯干加腿的总长代替身体比例验收。生成、局部合成、实际安装和实机验收分别记录。

- 以当前已验收设计和运行 manifest 为尺度依据；比较站姿、走路和跑步时保持相同身体尺度及脚部锚点，避免各自按包围框拉满导致头部或身高失真。
- 主角的基础图集沿用 [body-scale-v4](../../source-art/characters/2d-concepts/body-scale-v4/README.md) 校准：实际像素世界尺度为动作 `worldUnitsPerPixel` 乘 manifest 根部 `frameScaleFactors[无扩展名图像名][物理帧索引]`。局部修图、预览和后续接入均须读取这两个值；共用帧别名必须一致。以本轮用户指定的挥剑设计为基准，单独保持头部尺度，活动帧按躯干、大腿和小腿分别校准，不能把挥剑范围或弯腿后的外接框当成人物身高。
- 需要保持其他区域时，将模型输出作为局部候选，再用本地遮罩合成。提示词中的“只改头部”不是其他像素不变的保证；必要时比较遮罩外像素，检查遮罩边界是否完整覆盖旧轮廓，防止重影、断颈或残留原脸。
- 核对头型、脸型、发型、头身比例、腿长、跑姿前倾、手脚位置、武器携带位置、服装细节和透明边缘；序列帧还需检查跨帧身份、尺度和动作连续性。
- 保存输入来源、真实尺寸、模型/运行版本、工作流、提示词、种子、输出、耗时及验收结论。运行成功、出图成功或遮罩外像素不变，均不能单独证明美术效果合格。
- 试验结果单独保存，通过画质验收后再接入正式素材；失败小样明确标注原因，不用未通过的生成结果覆盖当前已验收资源。
